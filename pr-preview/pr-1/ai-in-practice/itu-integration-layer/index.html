Institutional Use Case Collection

Interdisciplinary Transformation University (ITU Austria)

Integration Layer: A Data Backbone for AI Readiness

  • Stage: 1–2 Coalition Forming / Governance & Strategic Foundations
  • Scope: Operational Readiness
  • Scale: Institution-wide infrastructure

What it is

The Integration Layer was a strategic infrastructure project to connect all internal and external university systems, replacing manual CSV-based data exchanges with automated, real-time integrations. It was designed to connect to a centralised data layer acting as a single source of truth for organisational data. The project was explicitly described as an AI-readiness enabler rather than an AI implementation in itself — the integration layer was intended to be the backbone of a future intelligent digital ecosystem.

Problem addressed

As a new university, ITU wanted to build a reliable data foundation capable of supporting future operations and automation. At the time, data was siloed across systems, manual CSV-based exchanges were slow and error-prone, and the absence of real-time synchronisation was unsustainable as the institution grew.

How it was built

The project was a top-down strategic initiative approved through the Change Forum. It was built using Microsoft Power Platform (Power Apps and Power Automate), Zapier, and Informatica, with support from external consultants. The integration layer ran in parallel with a separate data layer and data lake project, and all three were described as interdependent.

Cost & resources

Estimated cost was approximately €90,000, covering licensing, hosting, consultancy, and training. Around 6–8 internal staff worked on the project alongside external consultants.

Outcomes

No benefits had been realised at the time of submission. Phase 1, which involved connecting the LMS and CMS to the integration layer, was set to complete by September 30, 2026. Anticipated outcomes included automated real-time data integrations, a centralised single source of truth, rapid onboarding of new applications, scalable infrastructure, and a data governance and compliance framework to support future AI features.

Risks

Identified risks included undefined scope for future phases, unknown future application timelines, integration complexity, performance bottlenecks, scalability limitations, vendor lock-in, budget overruns, timeline delays, and data quality issues. These were managed continuously throughout the project during sprint cycles.
